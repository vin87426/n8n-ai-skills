# CWA 資料處理指南

只有在解析、正規化、儲存或驗證 CWA 資料時讀取本文件。

## 先分類資料形態

| 形態 | 常見結構 | 建議處理 |
|---|---|---|
| 測站觀測 | 測站 → 地理資訊 → 觀測時間 → 氣象因子 | 一列一測站一觀測時間；保留站碼與座標 |
| 行政區預報 | 地點 → 氣象因子 → 有效時段 → 參數 | 轉成一地點、一因子、一時段的 long table |
| 格網資料 | 時間、範圍、解析度、維度、格點值 | 保留座標軸、CRS／經緯度、維度順序與單位 |
| 影像中繼資料 | 產品時間、地理範圍、資源 URL | 原檔加 manifest；不要把影像 URL 當成觀測數值 |
| 統計資料 | 站點或行政區 × 統計期間 × 指標 | 保留統計期間、方法與缺值規則 |

先檢查實際回應。外層可能包含成功狀態、查詢資訊與 records；內層欄位大小寫和階層可能因資料集而異。成功旗標也可能因介面或版本呈現為布林值或字串；依當前文件與實際小範圍回應驗證明確的成功值，不使用一般 truthy 判斷。

## 建立欄位契約

對每個資料集明確定義：

- 必要欄位：缺少就停止該批次或告警。
- 選填欄位：缺少時填 null 並保留原因。
- 型別：先保留字串原值，再安全轉型。
- 單位：與數值一起保存，不依欄位名稱猜測。
- 時間角色：`observation_time`、`issue_time`、`valid_from`、`valid_to`、`retrieved_at`。
- 空間角色：station ID、座標、行政區、格網範圍、解析度。
- 品質旗標：原始代碼、轉換後狀態、是否通過合理範圍檢查。

## 處理特殊值

CWA 資料可能用字母或負數表示雨跡、故障、缺測或其他狀態，但代碼的適用欄位與語意必須以該資料集的說明文件為準。

採用以下模式：

```text
value_raw       原始值，例如 "T" 或 "-99"
value_numeric   可安全運算的數值，特殊值通常為 null
quality_code    原始特殊代碼
quality_status  依資料集文件映射後的語意
```

不要將所有資料集的 `-98`、`-99`、`T` 或 `X` 套用同一套全域定義。不要在不保留旗標的情況下把雨跡直接改成 0。

## 處理時間

1. 解析來源時間字串及 offset。
2. 保留原始字串與原始時區。
3. 另存 UTC ISO 8601 供排序與跨系統比較。
4. 預報資料同時保存發布時間與有效起訖時間。
5. 對日界、夏令時間或無 offset 的資料明示採用的時區假設。
6. 以 `retrieved_at` 計算延遲，不用系統處理完成時間冒充觀測時間。

## 驗證空間代表性

- 確認測站名稱與 station ID 沒有因同名或改名而混淆。
- 以座標計算距離，但同時考慮海拔、地形、海岸方向、島嶼與測站類型。
- 對格網確認緯經度順序、起點、遞增方向、nx／ny 與扁平陣列的展開方式。
- 影像或格網的地理範圍不代表每個位置都有相同品質。

## 保存與輸出

- 原始回應：以不可變方式保存，檔名或 metadata 包含 dataset ID 與擷取時間。
- 表格觀測：使用 CSV 供交換、Parquet 供分析；保留 schema 與單位。
- 格網：使用 NetCDF、Zarr 或其他能保存座標和 metadata 的格式。
- 影像：保存原始檔、checksum、產品時間、URL、範圍與擷取時間。
- 對使用者摘要：只輸出必要欄位，但附資料時間、來源與限制。

## 品質檢查

- 檢查必要欄位、型別、單位、合理範圍與時間單調性。
- 偵測測站筆數、null 比例或欄位集合的突然變化。
- 分開標記「來源缺值」、「解析失敗」與「超出合理範圍」。
- 對重複資料使用 dataset ID、空間識別、有效時間與版本資訊建立穩定鍵。
- 不以舊資料靜默補成最新資料；若使用 fallback，明示資料時間與原因。
