# 取得 CWA 氣象資料

## 遵守核心原則

- 優先使用 CWA 當下的官方資料與文件，不把本 skill 的範例值當成最新資訊。
- 先確認資料語意，再選端點；區分觀測時間、發布時間、預報有效時間與擷取時間。
- 將 API 授權碼視為密鑰。從環境變數或秘密管理工具讀取，不輸出、不寫入程式碼、不放進日誌。
- 保留原始回應與來源資訊，再做欄位轉換。不要因範例結構相似，就假設不同資料集共用 schema。
- 對所有結論標示資料集代碼、資料時間、時區與資料新鮮度。

## 執行流程

1. 明確化需求。
   - 確認地點、時間範圍、所需因子、輸出格式與用途。
   - 區分最新資料、短期歷史資料、預報、警特報、格網或檔案產品。
   - 地名有歧義時先解析行政區或座標；時間未指定時使用使用者意圖與資料所在地時區，並明示假設。

2. 選擇資料集與取得方式。
   - 從官方資料清單或 Swagger 查找 dataset ID，不憑名稱猜測。
   - 最新結構化資料優先選 REST datastore。
   - 圖像、壓縮檔、GRIB2 或其他檔案型產品選 File API。
   - 指定過去時間且資料集支援時，選 History API。
   - 需要端點、認證或重試細節時，讀取 [CWA API 指南](references/cwa-api.md)。

3. 擷取最小必要資料。
   - 優先用 `Authorization` header；若執行環境限制 header，再使用 URL query。
   - 對地點、時間、資料筆數與欄位套用官方支援的查詢參數。
   - 設定合理 timeout；只對可重試的暫時錯誤執行有限次退避重試。
   - 檔案下載支援時使用 ETag／`If-None-Match`，並允許官方文件要求的重新導向。

4. 驗證回應。
   - 檢查 HTTP 狀態、內容類型、成功旗標與錯誤訊息。
   - 比對該 dataset 的當前欄位說明或範例；不要只檢查 JSON 是否可解析。
   - 確認測站、地理範圍、單位、解析度、資料時間與請求相符。
   - 若平台公告 schema 異動，優先依公告與最新資料標準調整。

5. 正規化資料。
   - 保留 `raw_value`、原始時間字串、dataset ID 與擷取時間。
   - 將數值、單位與缺值旗標拆開；特殊代碼依資料集文件轉換，不套用全域規則。
   - 將時間轉成帶時區的 ISO 8601；需要跨系統使用時，同時保留 UTC 與原始時區。
   - 表格資料可整理為 CSV／Parquet；格網資料應保留時間、座標、維度與單位後再轉 NetCDF 或適合的地理格式。
   - 需要解析與品質檢查細節時，讀取 [資料處理指南](references/data-handling.md)。

6. 交付結果。
   - 先回答使用者真正需要的天氣資訊，再補充技術細節。
   - 列出來源名稱與官方連結、dataset ID、資料時間、查詢範圍與限制。
   - 若提供程式碼，使用可配置的 dataset ID、base URL 與秘密變數，並加入錯誤處理與 schema 檢查。

## 處理失敗與不確定性

- 授權失敗時停止重試，檢查授權碼來源與傳送位置，但不要顯示授權碼。
- 找不到資料集或欄位時，回到官方資料清單、Swagger 與公告查證，不自行替換成名稱相近的資料集。
- 觸發配額或限流時遵守伺服器指示，減少查詢、採快取並延後重試。
- 回應成功但 records 為空時，檢查時間範圍、地點拼法、發布時次與資料可用期間；將「查無資料」和「請求失敗」分開報告。
- 來源間不一致時，保留各自資料時間、位置與產品型態，說明差異，不直接平均。

## 最低輸出內容

至少包含：

- 查詢目標與時間範圍
- 官方來源與 dataset ID
- 資料時間、時區與擷取時間
- 主要結果及單位
- 缺值、延遲、空間代表性或 schema 限制
- 若是整合任務：可執行範例、秘密設定方式與驗證策略
