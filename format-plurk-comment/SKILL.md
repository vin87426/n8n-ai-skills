# 格式化 Plurk 留言

## 執行流程

1. 找出原文的核心回應、必要事實、行動、限制、網址與語氣。
2. 改寫成簡短、自然且直接回應原始噗文或上一則留言的一則留言。原文已自然且符合規則時保留其措辭；不要添加原文沒有的事實。
3. 只有在輸入已確認 Plurk 帳號時才加入 `@帳號:`；不要把顯示暱稱猜成帳號。
4. 依下列規則套用必要格式，不為了裝飾而增加長度。
5. 計算完整輸出的字元數，必要時簡化到 360 字元以內。
6. 只輸出最終留言文字。

## 使用允許的格式

- 一般文字：直接輸出。
- 提及：使用 `@使用者帳號:`，並保留已確認帳號的原始拼法。
- 網址：直接放入完整網址；需要說明時使用 `https://example.com (說明)`。
- 粗體或文件定義的底線：使用 `**內容**`。
- 斜體：使用 `*內容*`。
- 圖片或影片：直接放入完整網址，讓 Plurk 視情況產生預覽。
- 表情：可使用 Unicode Emoji。只有輸入已提供或可確定存在時才使用 Plurk 表情代碼；不要猜測代碼。

不要使用標題、引用、`[文字](網址)`、Markdown 程式碼區塊、Markdown 表格、JSON、包住整則留言的引號，或 `留言內容：` 等標籤。

## 強制 360 字元限制

- 將文字、空白、換行、標點、網址、提及、表情與格式符號全部計入最終長度。
- 超過限制時依序刪除空泛開場、重複資訊、贅詞、裝飾性換行、非必要強調與非必要表情，再合併句子並改用較短說法。
- 優先保留核心回應、使用者指定必留內容、已確認的提及及必要網址；次要細節或非必要網址可刪除。
- 不截斷或改寫網址，不破壞 `@帳號:`、`**...**` 或 `*...*` 的完整性，也不要自行建立短網址。
- 簡化後重新計數。若無法可靠判斷複合 Emoji 的計數方式，繼續縮短並保留安全餘量，不要貼近上限。
- 若使用者指定的必留項目彼此衝突或合計已超過限制，360 字元與只輸出留言本文的固定契約優先；刪除最低優先內容，不要超限或附加解釋。

## 輸出契約

最終回覆必須同時符合：

- 只有一則可直接貼到 Plurk 的留言文字。
- 不超過 360 字元。
- 沒有 JSON、Markdown 程式碼區塊、前綴、引號或額外說明。
