# 分析潛點預報

## 守住安全邊界

- 將結果定位為預報資料整合與風險分析，不宣稱「安全」、不保證可下水，也不取代官方、現場主管、潛導或船長決策。
- 先辨識官方封閉、雷雨、強風、熱帶系統、長浪、不可回收流向及高風險進出水等停止條件；不得以能見度或單一較佳指標抵銷。
- 將越遠期的預報表達成趨勢和候選時窗。對第 4–7 天避免精確承諾浪況、流況或能見度。
- 缺少潛點位置、地形或水下流資料時降低信賴度，不把區域模式直接當成潛點現況。

## 準備分析範圍

取得或合理解析：

- 潛點名稱、座標、當地時區、分析起訖日期與目標入／出水時段
- 岸潛、船潛、放流、自由潛水或浮潛等型態
- 海岸朝向、暴露方向、入水口、遮蔽、底質、岬角／水道、河口／排水口及已知危害
- 使用者經驗、流速／能見度偏好與團隊支援；只有在會實質改變比較時才要求補充

同名潛點或同一潛點包含多個暴露程度不同的入水口時，先確認精確位置。若無法確認，只做區域級比較、列出採用範圍與入口差異，不任選入口或把較遮蔽入口套用到整個潛點。

## 執行流程

1. 建立潛點暴露模型。
   - 判定波向與風向如何作用於海岸、入水口與主潛區。
   - 說明島嶼、岬角、灣澳、水深、底質與局部水道可能造成的遮蔽、聚焦、加速或再懸浮。

2. 收集最新預報與背景觀測。
   - 優先使用官方氣象／海洋機構、官方警示、浮標與潮位站，再使用可說明解析度與初始化時間的高解析模式。
   - 取得波浪／湧浪、風、潮位、海流、降雨／雷雨、水溫與可得的水色資訊。
   - 納入前 24–72 小時實際降雨、河川資料與最近觀測，評估模式初始狀態和濁水延遲。
   - 臺灣資料可使用 `get-cwa-weather-data` 的流程查找 CWA 官方 dataset。若該 skill 或 API 授權不可用，改用 CWA 官方公開預報／警示頁，再以方法透明的模式補足缺少變數；明確區分官方資料與補充來源。
   - 需要資料欄位、來源排序、地形轉譯與信賴度細節時，讀取 [預報證據指南](references/evidence-guide.md)。

3. 對齊逐時時間軸。
   - 將來源轉換到潛點當地時區，保留模型發布／初始化時間與預報有效時間。
   - 對未來 1–3 天優先使用逐時或每三小時資料。
   - 對未來 4–7 天聚合為早／午／晚或日尺度趨勢，並標示需要重新確認的時間。

4. 分析進出水。
   - 同時解讀浪高、最大浪風險、主週期、波向、湧浪分量與風向。
   - 分開分析預計入水與出水；檢查碎波、浪組、回抽、平台／階梯、低潮裸礁與替代出水點。
   - 不使用「浪高低於某值」作為普遍安全門檻，除非有潛點專屬、來源可靠的操作標準。

5. 分析潮汐與海流。
   - 區分潮位、潮位變化速率與潮流轉向；滿／乾潮不必然等於弱流。
   - 區分表層流與水下流，並考慮岬角、水道、航道、離岸方向及船隻回收能力。
   - 缺少潛點專屬流況時，只給區域推測與限制。

6. 推測能見度趨勢。
   - 綜合前期降雨、上游河川／排水、波浪擾動、底質、潮向、水色、葉綠素及歷史在地規律。
   - 沒有直接量測或近期回報時使用「偏清／中等／偏濁／資料不足」或寬區間，不宣稱精確公尺數。

7. 辨識停止條件並比較時段。
   - 先排除有明確安全危害的時段。
   - 再依進出水、水下流、天氣穩定性、能見度趨勢與信賴度比較，不用單一總分掩蓋致命弱點。
   - 若比較多個潛點，分別套用各自暴露方向與局部限制。

8. 評估信賴度並輸出。
   - 依預報時效、來源一致性、模型解析度、測站距離、潛點專屬資料及快速變化風險評為高／中／低。
   - 使用 [預報分析輸出模板](references/output-template.md)，刪除完全不適用的欄位，但不得省略資料更新時間、主要風險、最佳候選時窗、信賴度、缺口與重查時間。

## 表達結論

- 使用「條件相對較佳」、「預報上可考慮」、「對一般岸潛並不理想」或「需視團隊經驗與支援」等條件式用語。
- 避免「絕對安全」、「保證適合」、「一定可以」、「完全沒有流」與沒有直接證據的精確能見度。
- 對每個候選時窗同時列出為何較佳、仍存在的風險及失效條件。
- 明確指定何時改用 `dive-site-nowcast-analysis` 重新檢查；通常至少在出發前與下水前更新官方警示、雷達、浮標、風、浪與現場回報。

## 引用與時效

- 對可連結的來源附上直接網址或資料集頁，並標示模式名稱、發布／初始化時間與有效時間。
- 使用相對日期時同時寫絕對當地日期，避免週末、明天或跨時區誤解。
- 若無法存取最新預報，明示只能提供分析框架或基於使用者資料的條件式判讀。
