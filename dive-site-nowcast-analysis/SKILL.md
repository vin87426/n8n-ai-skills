# 分析潛點即時狀況

## 守住安全邊界

- 將結果定位為遠端資訊整合與風險分析，不宣稱「安全」、不核准下水，也不取代官方、現場主管、潛導或船長決策。
- 先處理官方封閉、雷擊、現場取消、無法安全進出水、流向不可回收區與快速惡化等停止條件；不得用良好能見度抵銷安全危害。
- 找不到關鍵即時資料時降低信賴度並清楚說明，不以舊資料或預報假裝現況。
- 若現場觀察或專業人員比遠端分析保守，採用較保守判斷。

## 準備分析基準

取得或合理解析：

- 潛點名稱、座標、當地時區與分析基準時間
- 預計入水及出水時間
- 岸潛、船潛、放流、自由潛水或浮潛等型態
- 入水口、海岸朝向、暴露方向、岬角／灣澳遮蔽、河口／排水口與已知危害
- 使用者經驗、團隊支援或限制；只有在會實質改變分析時才要求補充

同名潛點或同一潛點包含多個暴露程度不同的入水口時，先確認精確位置。若無法確認，只做區域級分析、列出採用範圍與入口差異，不任選入口或把較遮蔽入口套用到整個潛點。

## 執行流程

1. 建立當地時間軸。
   - 對齊現在、預計入水、預計出水及各來源的觀測時間。
   - 同時記錄發布／觀測時間、擷取時間、更新週期與延遲。

2. 先查硬性危害。
   - 查官方封閉、海岸或海域警示、雷擊與雷達、強風大雨、熱帶系統、港口或管理單位公告。
   - 任一明確停止條件成立時，先給出不建議下水的結論，再說明證據；不必為了湊齊一般海況而延後警示。

3. 收集最新觀測。
   - 優先使用潛點本地攝影機／感測器、最近且具代表性的浮標／潮位／流速站、官方雷達與河川資料、同日且位置明確的現場回報。
   - 優先蒐集現在、30 分鐘前、1 小時前與 3 小時前的序列；不可只取最新單點。若來源解析度較低，使用其原生時間點，不插值成不存在的觀測，並明示趨勢解析度限制。
   - 臺灣資料可使用 `get-cwa-weather-data` 的流程查找 CWA 官方 dataset。若該 skill 或 API 授權不可用，改用 CWA 官方公開觀測／警示頁並標示解析度，不因此改採過期快照。
   - 需要欄位、新鮮度、代表性與衝突判讀時，讀取 [即時證據指南](references/evidence-guide.md)。

4. 驗證資料是否代表潛點。
   - 比較距離、海岸方向、岬角兩側、外海／近岸、封閉港灣、水深與感測深度。
   - 將每個來源標成可直接代表、部分代表或僅供背景，並附理由。

5. 分析趨勢與預報偏差。
   - 將浪高、最大浪、週期、波向、風與陣風、潮位、流速、濁度、河川流量及雷達分類為改善、穩定、惡化或資料不足。
   - 對照近期預報；觀測持續偏離時，提高可信觀測的權重。

6. 轉譯成潛點影響。
   - 分開評估入水與出水時段的碎波、浪組、回抽、平台／階梯與替代出水點。
   - 結合波向、週期與地形推測 Surge；不要只用有效波高。
   - 結合潮位變化、表層流、風與地形評估漂離岸邊、繞岬角或進入航道的風險。
   - 將能見度證據分成直接量測與間接推論；沒有直接證據時只給趨勢或寬區間。

7. 預估未來 1–3 小時。
   - 找出潮流轉向、風向轉變、雷雨接近、浪持續建立、滿／乾潮及河川濁水延遲等轉折。
   - 以預計出水時間為共同終點；「現在可考慮」不代表能安全返回。

8. 評估信賴度並輸出。
   - 依資料新鮮度、在地性、多來源一致性、直接水下證據與變化速度評為高／中／低。
   - 使用 [即時分析輸出模板](references/output-template.md)，刪除完全不適用的欄位，但不得省略資料時間、主要風險、信賴度、缺口與現場確認事項。

## 使用結論分類

依序選擇最符合證據的一類：

1. 不建議下水
2. 建議等待並重新評估
3. 僅適合熟悉潛點且有相應支援的團隊
4. 目前條件可能可接受，但仍須現場確認

不要把結論簡化成單一分數。先說明停止條件與主要風險，再說明次要條件。

## 引用與時效

- 對可連結的即時來源附上直接網址或資料集頁，不只寫平台名稱。
- 清楚區分資料觀測時間與網頁更新時間。
- 使用相對時間時同時寫絕對當地日期與時間，避免「今天／剛剛」跨時區誤解。
- 若無法存取即時來源，明示只能提供分析框架或基於使用者資料的條件式判讀。
